這個網站是我的個人頁面，包含自我介紹、作品集、留言板，以及你正在看的這個 Blog。這篇文章記錄它用了哪些技術、為什麼這樣設計，還有最近一次翻修改了什麼。

## 技術選擇

| 分類 | 技術 |
| ---- | ---- |
| 前端 | Vue 3（Composition API）、TypeScript |
| 建置 | Vite |
| 路由 | Vue Router（History 模式） |
| 狀態 | Pinia + Composables |
| 後端 | Firebase Authentication、Cloud Firestore |
| 部署 | Vercel |

樣式全部用原生 CSS 寫，沒有用 UI 框架。

## 沒有自建伺服器

整個網站是純前端的 SPA。登入和資料都交給 Firebase：網頁直接跟雲端資料庫溝通，誰能讀、誰能寫，則由雲端上的**安全規則**把關。

也就是說，網頁本身可以被任何人看到，真正的安全防線是雲端的規則。以留言板為例，規則做到的是：

- 所有人都可以讀留言
- 只有登入的人能留言，而且只能用自己的帳號留言
- 留言長度有上限，時間以伺服器為準
- 留言送出後不能修改
- 只有管理員可以刪除

## 第三方登入與即時留言

登入是用彈出視窗登入 Google 或 GitHub。登入狀態只在網站啟動時設定一次，所有頁面共用同一份，不會各自重複檢查。

留言板會即時同步：有人新增或刪除留言，所有開著頁面的人都會馬上看到，不用重新整理。留言時間以伺服器為準，避免使用者電腦時間不準造成順序錯亂。

## SPA 路由在 Vercel 上的坑

Vue Router 用 History 模式，網址裡沒有 `#`。但直接打開 `/blog` 這類網址時，Vercel 會去找一個叫 blog 的檔案，找不到就回 404。解法是在部署設定裡讓所有網址都先回到網站首頁，再由前端路由決定要顯示哪一頁。

## 一次大翻修

網站做好一段時間後，我回頭整理了一次：

1. **清除死碼**：刪掉連正式版都開著的假資料介面，以及沒人用的程式和元件。
2. **統一名稱與 SEO**：網站名稱統一為 Tim Wu，補上頁面語言、網站描述、社群分享預覽與網站圖示。
3. **修好留言板**：原本兩個畫面各自保存一份留言資料，送出後畫面不會馬上更新；改成共用同一份之後才正常。順便不再把留言者的 email 存進資料庫，並加上管理員刪除功能。
4. **Blog 真的能寫文章了**：文章就是 Markdown 檔，上傳到 GitHub 後網站會自動更新，不需要後台。

## 文章是怎麼運作的

每篇文章是一個 Markdown 檔，開頭寫好標題和日期。建置網站時會自動讀進所有文章，打開文章頁時再用 markdown-it 轉成網頁。每篇文章有自己的網址，例如這篇是 `/blog/how-this-site-was-built`。
