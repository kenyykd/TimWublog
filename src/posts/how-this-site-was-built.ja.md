このサイトは私の個人ページで、自己紹介、作品集、掲示板、そして今読んでいるこの Blog があります。この記事では、使っている技術、なぜこの設計にしたのか、そして最近のリニューアルで何を変えたのかをまとめます。

## 技術スタック

| 分類 | 技術 |
| ---- | ---- |
| フロントエンド | Vue 3（Composition API）、TypeScript |
| ビルド | Vite |
| ルーティング | Vue Router（History モード） |
| 状態管理 | Pinia + Composables |
| バックエンド | Firebase Authentication、Cloud Firestore |
| デプロイ | Vercel |

スタイルはすべて素の CSS で書いていて、UI フレームワークは使っていません。

## 自前のサーバーを持たない

サイト全体はフロントエンドだけの SPA です。ログインとデータは Firebase に任せていて、ページから直接クラウドのデータベースとやり取りします。誰が読めて誰が書けるかは、クラウド側の**セキュリティルール**が判断します。

つまり、ページ自体は誰でも見られるもので、本当の防御線はクラウドのルールです。掲示板の場合、ルールで実現していることは次のとおりです。

- 誰でもメッセージを読める
- 書き込めるのはログインした人だけで、自分のアカウントとしてしか書き込めない
- メッセージの長さには上限があり、時刻はサーバー基準
- 送信したメッセージは編集できない
- 削除できるのは管理者だけ

## ソーシャルログインとリアルタイムの掲示板

ログインはポップアップで Google または GitHub にサインインする方式です。ログイン状態はサイトの起動時に一度だけ設定し、すべてのページで同じものを共有しているので、ページごとに何度も確認することはありません。

掲示板はリアルタイムで同期されます。誰かがメッセージを追加・削除すると、ページを開いている全員にすぐ反映され、再読み込みは不要です。投稿時刻はサーバー基準なので、利用者のパソコンの時計がずれていても順番が狂いません。

## Vercel で SPA のルーティングにハマった話

Vue Router は History モードなので、URL に `#` が付きません。ところが `/blog` のような URL を直接開くと、Vercel は blog というファイルを探しに行き、見つからずに 404 を返してしまいます。解決策は、デプロイ設定ですべての URL をいったんトップページに戻し、どのページを表示するかはフロントエンドのルーターに任せることでした。

## 大規模なリニューアル

サイトを作ってしばらくしてから、一度まとめて整理しました。

1. **不要なコードの削除**：本番環境でも動いていた偽のデータ API や、使われていないプログラムやコンポーネントを削除しました。
2. **名前と SEO の統一**：サイト名を Tim Wu に統一し、ページの言語、サイトの説明、SNS でシェアしたときのプレビュー、サイトアイコンを追加しました。
3. **掲示板の修正**：もともと二つの画面がそれぞれ別々にメッセージのデータを持っていて、送信しても画面がすぐに更新されませんでした。同じデータを共有するようにして直しました。ついでに投稿者のメールアドレスをデータベースに保存しないようにし、管理者による削除機能も追加しました。
4. **Blog で本当に記事が書けるように**：記事は Markdown ファイルで、GitHub にアップロードすればサイトが自動で更新されます。管理画面は必要ありません。

## 記事の仕組み

記事は一本ずつ Markdown ファイルになっていて、冒頭にタイトルと日付を書きます。サイトのビルド時にすべての記事を自動で読み込み、記事ページを開いたときに markdown-it でウェブページに変換します。記事にはそれぞれ URL があり、たとえばこの記事は `/blog/how-this-site-was-built` です。
